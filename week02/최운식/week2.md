# 3장. 자바 가상 머신 개요

성능에 관심이 있는 개발자라면 자바 가상 머신 기술 스택의 기본을 이해하는 것이 중요함. 자바 가상 머신 인터프리터의 기본 동작은 `while` 루프 안에 `switch` 문이 들어있는 구조로 이해하면 됨.

## 클래스 로딩 메커니즘

프로그램을 시작하기 전에 자바 가상 머신이 해당 클래스를 로드해야 하고, 이를 위해 자바 클래스 로딩 메커니즘이 사용됨.

### 클래스 로더 체인

- **부트스트랩 클래스 로더**: `java.lang.Object`, `Class`, `ClassLoader`와 같은 필수적인 클래스를 불러옴. 자바 8에서 쓰이던 모놀리식 자바 가상 머신 런타임을 복원하는 호환성 모드(클래스패스 모드)는 더 이상 존재하지 않음.
- **플랫폼 클래스 로더**: 기본 시스템의 나머지 부분을 로드하며, 부트스트랩 클래스 로더를 부모로 가짐. 새로운 모듈 시스템에서는 자바 프로세스를 부트스트랩하는 데 필요한 코드가 훨씬 줄어들었고, 그만큼 부트스트랩 로더의 범위가 줄고 플랫폼 로더가 이를 처리함.
- **애플리케이션 클래스 로더**: 마지막으로 생성되며, 클래스 경로에서 사용자 클래스를 로드하는 역할을 함.

자바는 프로그램 실행 중 클래스가 처음 참조될 때 그 의존성을 로드함. 못 찾으면 부모 클래스 로더에 위임하고, 한 클래스는 한 번만 로드됨.

### 모듈 시스템 (자바 9+)

자바 9부터 모든 자바 가상 머신은 모듈화됨. 애플리케이션 자체가 모듈화되어 있지 않더라도 실행 시 반드시 모듈 그래프가 생성되고, 이 그래프는 방향이 있는 비순환 그래프(DAG)여야 함. 그렇지 않으면 오류가 남.

모듈 그래프의 장점:

- 필요한 모듈만 로드
- 모듈 간 메타데이터의 유효성을 시작 시점에서 확인

## 바이트코드와 javac

`javac`의 역할은 자바 코드를 `.class` 파일로 변환하여 바이트코드를 생성하는 것. `javac`는 컴파일 과정에서 최적화를 거의 수행하지 않음.

바이트코드는 특정 머신 아키텍처에 종속되지 않은 중간 표현이며, 자바 가상 머신이 지원하는 모든 플랫폼에서 실행될 수 있음(코틀린 같은 다른 JVM 언어도 마찬가지).

`HelloWorld.class` 파일의 바이트코드 설명은 생략.

## 핫스팟

핫스팟은 자바 구현의 성능을 획기적으로 개선하는 변화를 도입함. 제로 코스트 추상화 중 "사용하는 경우, 직접 코딩하는 것보다 더 나은 코드"라는 문구는 중요한 의미를 가짐 — 컴파일러 같은 시스템이 개발자가 직접 작성할 수 있는 코드보다 더 최적화된 코드를 생성한다는 뜻.

### JIT 컴파일러

JIT 컴파일은 애플리케이션이 해석 모드에서 실행되는 동안 실행 빈도가 높은 코드 부분을 관찰하면서 작동함. JIT 컴파일을 거치고 나면 실제로 실행되는 코드는 원래 작성된 소스 코드와 매우 다르게 변함.

## 자바 가상 머신 메모리 관리

가상 머신이 제공하는 핵심 두 가지 기능 중 하나가 핫스팟의 컴파일 하위 시스템이고, 두 번째가 자동 메모리 관리임.

자바는 가비지 컬렉션을 통해 자동으로 관리되는 힙 메모리를 도입함. 자바 가상 머신이 더 많은 메모리 할당이 필요할 때, 더 이상 필요하지 않은 메모리를 회수하고 재사용하는 비결정적 프로세스를 수행함.

문제는 이 과정에서 정지된 세상(STW, Stop-The-World)이 발생한다는 것.
