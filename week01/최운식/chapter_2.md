## 2장 성능 테스트 패턴

### 2.1. 성능 테스트 유형

성능 테스트를 목적에 따라 여러 유형으로 나눈다.

| 유형                      | 질문              | 부하 패턴             | 목적                          |
| ----------------------- | --------------- | ----------------- | --------------------------- |
| 지연(Latency) 테스트         | 종단 트랜잭션 시간은?    | 일정                | 응답시간 분포 측정                  |
| 처리율(Throughput) 테스트     | 동시에 몇 건 처리 가능?  | 점증                | 최대 TPS 탐색                   |
| **부하(Load) 테스트**        | **이 부하를 견디는가?** | **예상 수준에서 일정 유지** | **SLA 충족 검증**               |
| **스트레스(Stress) 테스트**    | **어디서 무너지는가?**  | **한계까지 점진적 증가**   | **breaking point/Elbow 탐색** |
| 내구성(Soak/Endurance) 테스트 | 오래 돌리면 이상 생기나?  | 중간 부하 장시간         | 메모리 누수·리소스 고갈 탐지            |
| 용량 계획(Capacity) 테스트     | 미래 트래픽 감당 가능?   | 시나리오별             | 증설 계획                       |
| 저하(Degradation) 테스트     | 부분 장애 시 어떻게?    | 일부 컴포넌트 다운        | 복원력 검증                      |

- **Load Test** = "**예상되는(특정) 부하**에서 시스템이 SLA를 만족하며 **정상 동작**하는가"를 본다. 부하를 일정하게 유지하고 응답시간·에러율을 관찰한다. **합격/불합격 판정**이 목적.
- **Stress Test** = 부하를 **점점 키워서 한계점(breaking point)을 찾는다**. 처리율이 더 이상 안 오르고 응답시간이 급증하는 지점(= **Performance Elbow**, 1장에서 배운 개념)을 찾는다. **시스템의 천장이 어디인지**를 아는 게 목적.

> 정리: **Load = "버티나?"(정상 범위 검증), Stress = "어디서 부러지나?"(한계 탐색).**

### 2.2. 기본 베스트 프랙티스

성능 테스트 기본 원칙

1. **운영 환경과 최대한 동일한 환경에서 측정하라.** 하드웨어·OS·JVM 버전·힙 설정·데이터 규모·네트워크가 다르면 JIT·GC·캐시 동작이 달라져 결과를 신뢰할 수 없다. 
2. **현실적인 데이터·트래픽 패턴을 사용하라.** 합성 데이터는 캐시 히트율, 인덱스 선택성, 데이터 분포(long-tail)를 왜곡한다. 실제 분포를 반영해야 측정이 의미를 가진다.
3. **한 번에 하나만 바꾸고, 반복 측정해 통계로 판단하라.** 여러 변수를 동시에 바꾸면 원인을 분리할 수 없다. 단일 측정값(평균 하나)이 아니라 분포(분산·표준편차·백분위)로 판단한다.

### 2.3 성능 테스트 환경이 Production과 동일해야 하는 이유

성능 측정 결과는 **실행 환경에 극도로 민감**하다. 환경이 다르면 측정값 자체가 무의미해진다. 

주요 차이 요인:
- **JIT 컴파일**: CPU 명령어셋(AVX 등)·코어 수에 따라 인라이닝·벡터화 결과가 달라진다. 워밍업이 끝난 코드의 속도가 환경마다 다르다.
- **GC 동작**: 힙 크기·코어 수에 따라 GC 알고리즘 선택과 STW 빈도/길이가 달라진다. 작은 힙에서 안 나던 Full GC가 운영 힙에서 터질 수 있다.
- **데이터 규모**: 테스트 DB가 작으면 인덱스가 전부 메모리에 올라가 디스크 I/O가 안 잡힌다. 운영 규모에서야 캐시 미스·디스크 시크가 드러난다.
- **네트워크·OS·컨테이너**: 지연(latency), OS 스케줄러, cgroup CPU/메모리 제한, NUMA 배치가 모두 결과에 영향. (3장 하드웨어/OS 내용과 직결)
- **Tail latency(p99/p999)**: 평균은 환경 차이에 둔감하지만, **상위 백분위는 환경 차이에 폭발적으로 민감**하다. 실제 사용자 경험을 반영하는 지표라 더 중요하다.
